- **Concrete Friction / Findings Observed During Run**:
  1. **Asymmetric `structuredContent` nesting across tools**: Calling `tools/call` on `search_voices` returns items nested at `result.structuredContent.data.voices` (with envelope keys `release_id`, `total`, `truncated`, `data`), whereas `get_voice_packet` returns the voice packet fields directly under `result.structuredContent.data` (`instructions`, `target`, `voice_id`). Parsing `.structuredContent.voices` uniformly across calls failed on initial inspection until probing `Object.keys(sc.data)`.
  2. **Receipt string buried at the bottom of `instructions` & mid-session MCP config loading**: The Runx proof line (`Receipt: https://runx.ai/r/...`) is appended as plain text at the end of `data.instructions` (with `receipt_url` absent as an explicit JSON field in `structuredContent.data`), requiring downstream clients to regex-extract it from prose instructions. Separately, writing `~/.gemini/config/mcp_config.json` mid-session (with PowerShell `ConvertTo-Json` escaping `&` as `\u0026` under legacy `"serverUrl"`) required waiting for a fresh session / server refresh before Antigravity would expose the tools natively inside the turn.

- **One Concrete Change I Would Make**:
  - Expose a structured `receipt_url` property on `structuredContent` (for example, `structuredContent.meta.receipt_url` alongside `structuredContent.data`) and unify `structuredContent` collection naming across `search_voices`, `get_voice`, and `get_voice_packet`, while keeping the trailing `Receipt: https://runx.ai/r/...` instruction line for interactive chat clients.
